== Overview

Quintauris' machine meta-model defines the structure and properties of machine models employed across the {project}.

The top-level machine meta-model is a composition of smaller, more purpose-specific meta-models. The following is a simplified, top-level description of the meta-model hierarchy:

== Evaluated expressions

Attributes marked `Yes` in the `Expression` column are strings that shall be evaluated by model consumers to produce an integer result (e.g. `4096 * 8` o `4K * 16`).

Supported operators are:

* `()`: parentheses for grouping and precedence
* `+`, `-`, `*`, `/`: arithmetic operators
* `%`: modular division

Supported built-in functions are (both can take any number of parameters):

* `min()`
* `max()`

The following number formats are supported:

* Signed integer in base 10
* Unsigned intenger in base 16, prefixed by `0x`
* Signed decimal, using `.` as decimal separator

The following number suffixes are supported:

* `K` multiply by `1024` (e.g. `4K = 4*1024 = 4096`)
* `M` multiply by `1048576`
* `G` multiply by `1073741824`
* `k` multiply by `1000` (e.g. `4k = 4*1000 = 4000`)
* `m` multiply by `1000000`
* `g` multiply by `1000000000`

Values resulting from expression evaluation, signed or unsigned, must have an integral part representable in 63 bits or less. Decimal values will be rounded down to the closest integer.

== Declaration

It is possible to declare, either inline or `import` ing them, model elements in the following contexts:

* <<_machine>>: <<_peripheral>>s and <<_addressable>>s
* <<_peripheral>>: <<_addressable>>s
* <<_addressables>>: <<_addressable>>s and <<_register>>s
* <<_register>>: <<field>>s

 under a user-defined name. For example, the follwing code brings the model entity defined in `riscv/model/ns16550/model.json` to the current context <<_machine>> context, under the name `ns16550`:


----
  "declarations": {
    "ns16550": {
      "import": "riscv/model/ns16550/model.json"
    }
  }
----

Alternatively, `ns16550` can also be declared inline:

----
  "declarations": {
    "ns16550": {
      "peripheral": {
        "name": "uart_ns16550",
        "addressables": {
          ...
        }
      }
    }
  }
----

Now `ns16550`, no matter whether it  which can be used by <<_instance>>s of produce `ns16550` instances under `peripherals`:

----
  "uart0": {
    "instance_of": "ns16550",
    "peripheral": {
      "base": "0x10000000"
    }
  },
----

`substitutions` can be used to apply custom changes to the imported entity, for example:

----
  "declarations": {
    "ns16550": {
      "import": "riscv/model/ns16550/model.json"
      "substitutions": {"FOO": "BAR"}
    }
  }
----

will replace every occurence `$FOO` in `riscv/model/ns16550/model.json` string values with `BAR`.

== Instance

----
  "uart0": {
    "instance_of": "ns16550",
    "peripheral": {
      "base": "0x10000000"
    }
  },
----

== Register

Registers are word-aligned data instances within <<_addressable>>s. How individual registers are accessed is determined by the register's `class` attribute:

`memory_mapped`:: register is accessed via common fetch/store instructions on the register's address (parent's `offset` + `offset` determines the absolute address)
`control_status`:: register is accessed via direct RISC-V's CSR read/write instructions (parent's `offset` + `offset` determines the CSR index)

=== Constraints

ctr_fild_001:: `position` must be an integer number in the range `[-w, w - 1]` where `w` is the value of the `width` attribute from the enclosing <<_register>>
ctr_fild_002:: `length` must be an integer number in the range `[1, w - p]` where `w` is the value of the `width` attribute from the enclosing <<_register>>, and `p` is the value of `position`
ctr_fild_003:: <<_value>> keys shall conform to the following regular expression: `[a-zA-Z]+[0-9a-zA-Z_]*`
ctr_fild_004:: In `on_read` values `clear`, `set`, `toggle` and `modify` are mutually exclusive
ctr_fild_005:: `on_write` keys shall conform to one of the following regular expressions: `b[01]+` (binary value), `h[0-9a-fA-F]` (hexadecimal value), `d?[0-9]+` (decimal value) or `any` (any value)
ctr_fild_006:: `on_write` keys shall either be a list of numerical values, or just `any`
ctr_fild_007:: In `on_write` values `clear`, `set`, `toggle` and `modify` are mutually exclusive
ctr_fild_008:: Each element of `ranges` must be a 2-element array of strings that evaluate to integer numbers
ctr_fild_009:: If both `values` and `ranges` are defined, values in `values` must all be contained by `ranges`
ctr_fild_010:: `on_reset/__reset-name__` shall reference a valid <<_reset_type>> defined at <<_machine>> level
ctr_fild_011:: `on_reset/__reset-name__/value` shall be valid base-2 (i.e. binary) values, with no more bits than `length` bits
ctr_fild_012:: `on_reset/__reset-name__/mask` shall be valid base-2 (i.e. binary) values, with no more bits than `length` bits
ctr_fild_013:: <<_indexing>> keys shall conform to the following regular expression: `[a-zA-Z]+[0-9a-zA-Z_]*`
ctr_fild_014:: If `hw_volatile` is `true`, then the parent <<_register>> `hw_volatile` attribute shall be also `true`
ctr_fild_015:: Values defined by `on_reset/__reset-type__` shall not contradict those under enclosing <<_register>>'s `on_reset/__reset-type__`
